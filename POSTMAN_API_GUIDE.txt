1. SYSTEM OVERVIEW & ARCHITECTURE
================================================================================
This personalized RSVP system gives every invited guest or family a unique,
cryptographically secure 12-character random token.

Key Features:
- Secure URLs: Guest URLs look like:
  https://weeding-test.onrender.com/rsvp/0qasLjTBkVcZ
- No database IDs, phone numbers, or guest names are exposed in the link.
- Zero Login: Guests do not need passwords, accounts, or email verification.
- Family Attendance: Family invitations include individual checkboxes for every
  family member so each person's attendance is tracked accurately.
- Personalized Welcome: When opened on a phone or desktop, the page warmly
  welcomes the guest by name at the top of the royal invitation arch.
- Per-Guest Celebration Permissions:
  Enable or disable specific celebrations for each guest/family directly via
  Postman. Their personalized link will only display the celebrations they are
  invited to!
- Manual Code Entry: Guests who open the main homepage can click
  "Have a personalized invitation code?" and enter their 12-character token.

2. QUICK START: IMPORTING THE PRE-CONFIGURED POSTMAN COLLECTION
================================================================================
A ready-to-use Postman collection is already included in your project root:
File: Wedding_Personalized_RSVP.postman_collection.json

To import it into Postman:
1. Open Postman.
2. Click the "Import" button (top left corner).
3. Drag and drop the file `Wedding_Personalized_RSVP.postman_collection.json`
   (or click "files" and browse to your DIDI_Wedding folder).
4. Click "Import".
5. The collection "Wedding Invitation - Personalized RSVP System API" is ready!
6. By default, it uses the live URL:
   {{baseUrl}} = https://weeding-test.onrender.com
7. The test script in "Add Guest (Family)" automatically stores the generated
   token and ID into variables `{{guestToken}}` and `{{guestId}}` so you can run
   subsequent requests immediately without copy-pasting!

3. MANUAL POSTMAN SETUP (STEP-BY-STEP)
================================================================================
If you prefer to configure Postman manually:

Step 1: Create an Environment in Postman
- Click "Environments" on the left sidebar.
- Click "+" (Create Environment) and name it "Wedding Production".
- Add the following variables:
  * baseUrl    : https://weeding-test.onrender.com
  * guestId    : 1
  * guestToken : 0qasLjTBkVcZ
- Click "Save" and select "Wedding Production" in the top-right environment dropdown.

Step 2: Required Headers
- For all POST, PUT, and PATCH requests, make sure to add:
  Header: Content-Type
  Value:  application/json

- For GET requests, no special headers are required.

4.1 Admin: Create Family Guest (All Celebrations Default)
--------------------------------------------------------------------------------
Creates a new guest family entry, creates individual records for each member,
and automatically generates a secure 12-character alphanumeric token.
By default, all 4 celebrations are enabled if omitted.

- Method: POST
- URL: {{baseUrl}}/api/guests
- Header: Content-Type: application/json

Request Body (raw JSON):
{
  "name": "Sharma Family",
  "type": "FAMILY",
  "members": [
    "Rajesh Sharma",
    "Sunita Sharma",
    "Rahul Sharma"
  ]
}

  "id": 1,
  "name": "Sharma Family",
  "type": "FAMILY",
  "token": "0qasLjTBkVcZ",
  "rsvpLink": "https://weeding-test.onrender.com/rsvp/0qasLjTBkVcZ",

    "MEHENDI",

4.7 Admin: Enable / Disable Specific Celebrations (Dedicated Endpoint)
--------------------------------------------------------------------------------
Enables or disables celebrations for a guest or family at any time with a
single PATCH request. The website itinerary updates immediately!

- Method: PATCH
- URL: {{baseUrl}}/api/guests/{{guestId}}/events
- Header: Content-Type: application/json

Valid Celebration Keys:
  * "MEHENDI"   - Mehendi Ceremony (Saturday, 14 Feb 2027, 04:00 PM)
  * "HALDI"     - Haldi Ceremony (Sunday, 15 Feb 2027, 10:00 AM)
  * "WEDDING"   - Wedding Ceremony & Baraat (Sunday, 15 Feb 2027, 07:00 PM)
  * "RECEPTION" - Royal Reception & Dinner Banquet (Sunday, 15 Feb 2027, 09:30 PM)

Example A: Enable Only Wedding & Reception
Request Body:
{
  "allowedEvents": [
    "WEDDING",
    "RECEPTION"
  ]
}

Example B: Enable Only Reception (Dinner Banquet)
Request Body:
{
  "allowedEvents": [
    "RECEPTION"
  ]
}

Example C: Enable All 4 Celebrations
Request Body:
{
  "allowedEvents": [
    "MEHENDI",
    "HALDI",
    "WEDDING",
    "RECEPTION"
  ]
}

Expected Response (200 OK):
{
  "id": 1,
  "name": "Sharma Family",
  "type": "FAMILY",
  "token": "0qasLjTBkVcZ",
  "rsvpLink": "https://weeding-test.onrender.com/rsvp/0qasLjTBkVcZ",

4.8 Admin: Soft-Disable / Enable Invitation
--------------------------------------------------------------------------------
Allows you to disable an invitation link without deleting the record. When a
guest visits an INACTIVE link, the website informs them that the invitation
is no longer active and gives them a button to contact the host.

- Method: PATCH
- URL: {{baseUrl}}/api/guests/1/status
- Header: Content-Type: application/json

To Disable:
Request Body (raw JSON):
{
  "status": "INACTIVE"
}

To Re-Enable:
Request Body (raw JSON):
{
  "status": "ACTIVE"
}

Expected Response (200 OK):
{
  "id": 1,
  "name": "Sharma Family",
  "status": "INACTIVE"
}

5. HOW CELEBRATIONS PERMISSION & ITINERARY WORK
================================================================================
When a guest visits their personal link (e.g. /rsvp/{token}):
1. The frontend fetches their invitation record from `/api/rsvp/{token}`.
2. The response includes `allowedEvents: ["WEDDING", "RECEPTION"]`.
3. In the Royal RSVP Section:
   - The card shows: "Invited Functions: [Wedding] [Reception]".
4. In the Celebrations Itinerary Section:
   - A royal badge appears:
     "✨ Sacred Itinerary specially curated for [Guest Name]"
   - The ceremony list ONLY renders the cards enabled for that guest!
     (e.g., Mehendi and Haldi are hidden, and only Wedding and Reception appear).
5. For general visitors without a token (or visitors opening `/`):
   - All 4 standard royal ceremonies are shown.

6. COMPLETE END-TO-END WORKFLOW (HOW TO USE)
================================================================================
Step 1: In Postman, run "Add Guest (Custom Celebrations)"
  - Body:
    {
      "name": "Malhotra Family",
      "type": "FAMILY",
      "members": ["Sunil Malhotra", "Geeta Malhotra"],
      "allowedEvents": ["WEDDING", "RECEPTION"]
    }
  - Send the request.

Step 2: Copy the generated `rsvpLink` from the response
  - Example: `https://weeding-test.onrender.com/rsvp/9K3mP8Za1xQw`

Step 3: Send via WhatsApp / SMS
  - "Dear Malhotra Family, we joyfully invite you to the wedding of Chandrika & Xudong! Please RSVP here: https://weeding-test.onrender.com/rsvp/9K3mP8Za1xQw"

Step 4: Change enabled celebrations anytime:
  - If you decide later to also invite them to Haldi:
    Run `PATCH {{baseUrl}}/api/guests/{{guestId}}/events` with:
    { "allowedEvents": ["HALDI", "WEDDING", "RECEPTION"] }
  - Their existing link updates automatically without needing a new URL!

7. ERROR CODES & TROUBLESHOOTING
================================================================================
400 Bad Request:
  - Cause: Missing "name" in POST /api/guests or invalid JSON.
  - Solution: Ensure "name" is provided and JSON syntax is valid.

404 Not Found:
  - Cause: Token does not exist or guest ID does not exist.
  - Website: Shows "Invitation Not Found" screen with link back to homepage.

403 Forbidden:
  - Cause: Attempting to submit RSVP for an invitation with status "INACTIVE".
  - Website: Shows "Invitation Inactive" screen advising to contact host.
